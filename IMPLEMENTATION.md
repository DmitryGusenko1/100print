# Задание Codex: единая память AI-помощников

## Цель
Пользователь продолжает работу с двух компьютеров и телефона через одного Telegram-бота. История, решения, задачи и состояние проекта сохраняются на VPS и доступны после перезапуска. Репозиторий хранит код и документацию; личная переписка и секреты в Git не попадают.

## Порядок работы
1. Прочитай инструкции репозитория и проверь доступную среду. Если есть SSH-доступ к VPS, изучи существующие сервисы и базы без изменения данных. Не считай доступ к GitHub доступом к VPS.
2. Реализуй и проверь приложение локально, даже если доступ к серверу пока отсутствует. Работай в отдельной ветке, создай PR с результатом и проверками.
3. Подготовь установку через systemd без Docker. Перед развертыванием проверь существующие порты, сервисы и пользователей; не изменяй существующие сайты и ботов. Не запускай второй polling-процесс с токеном действующего бота.
4. Если для развертывания не хватает доступа, объясни пользователю одно простое действие за раз. Не проси присылать приватные ключи и пароли в переписку.

## Первый рабочий этап
Python, PostgreSQL, Telegram-бот и HTTP API общей памяти.
- Данные: владельцы, проекты, диалоги, сообщения, решения, задачи, версии краткого состояния проекта.
- Для каждого сообщения: источник, внешний ID, роль, время, проект и диалог. Уникальность внешнего ID исключает дубли при повторной доставке.
- Сначала надежно сохранить входящее сообщение, затем получить контекст и вызвать AI, затем сохранить ответ и отправить пользователю. Учитывать сбои AI и Telegram, не выдавать ошибку за успешный ответ.
- Перед ответом получать последние сообщения, состояние проекта и релевантную историю в пределах лимита контекста. Начать с полнотекстового поиска PostgreSQL; векторы необязательны.
- Решения и состояние содержат ссылки на сообщения-источники. Автоматические выводы отделены от явно подтвержденных пользователем решений.
- Команды /start, /projects, /project, /status. Смена проекта сохраняется на сервере.
- Доступ только разрешенным Telegram ID; проверять доступ перед сохранением и чтением данных. API требует отдельный ключ и проверку владельца проекта для каждого запроса.
- Настройки и ключи через переменные окружения. Предусмотреть совместимый с OpenAI API провайдер; не считать платную подписку ChatGPT API-ключом.
- Миграции базы, журналирование без секретов и текстов личных сообщений по умолчанию, healthcheck.
- Резервное копирование PostgreSQL и инструкция проверенного восстановления. Копии вне Git; указать, что копия на том же VPS не защищает от потери VPS.

## API
Добавление сообщений с защитой от дублей; получение контекста проекта; чтение и изменение задач, решений и состояния. Ограничения размера запросов и истории. На VPS по умолчанию слушать localhost; внешний доступ только через HTTPS с аутентификацией.

## Проверки
- Сообщение с компьютера доступно при продолжении с телефона в том же Telegram-аккаунте.
- После перезапуска сохраняются история и выбранный проект.
- Повторная доставка не создает дубли.
- Чужой Telegram ID и неверный API-ключ не получают доступа; нельзя прочитать чужой проект по ID.
- Сбой AI не теряет входящее сообщение и не создает фиктивный ответ.
- Миграции и восстановление резервной копии проверены на отдельной тестовой базе.

## Документация и результат
README.md: назначение, установка, запуск, настройки и ограничения.
STATUS.md: что реализовано, что проверено, что еще не запущено.
.env.example: только пустые значения или явно вымышленные примеры.
В отчете дать ссылку на PR, результаты проверок и один следующий шаг для пользователя.

## Граница интеграции
Создание базы и API само по себе не подключает обычные чаты ChatGPT и другие сессии Codex к памяти. Не обещать автоматический захват их переписки. Telegram сохраняет только сообщения, обработанные ботом. Старые чаты импортируются отдельным явным действием. Подключение ChatGPT/Codex через поддерживаемый инструмент или MCP — отдельный проверяемый этап после запуска первого рабочего контура.
