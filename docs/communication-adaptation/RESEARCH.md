# Адаптация общения Hermes: исследование и решение
Дата: 2026-11-09. Исследование по официальным источникам. Возможности онлайн-документации могут отличаться от установленной версии: исполнитель обязан проверить локальные команды и схему конфигурации.

## Решение
Основной готовый стек: встроенные memory/USER.md, session_search и background review Hermes + официальный Honcho memory provider для накопительного user modeling. Начать с работающей встроенной памяти без ожидания внешнего сервиса, затем подключить Honcho в тот же существующий профиль. Это адаптация контекста/памяти, а не обучение весов LLM. Не устанавливать несколько конкурирующих внешних memory providers.

## Сравнение
| Инструмент | Готовая функция | Применимость |
|---|---|---|
| Hermes USER.md + memory + background review | Сохранение предпочтений общения, изменение записей по обратной связи, поиск прошлых сессий | Обязательный первый слой: уже принадлежит используемому агенту; проверить, включён ли и действительно ли пишет |
| Honcho | Анализ разговоров, меняющаяся модель пользователя, peer cards/conclusions, внедрение контекста в следующие запросы | Лучшее соответствие этой задаче благодаря готовому провайдеру Hermes; доступен локально и как облачный сервис |
| LangMem prompt_memory/metaprompt/gradient | Оптимизация промпта по истории и обратной связи | Хорош для последующего контролируемого сравнения вариантов style prompt; сейчас не добавлять второй цикл автоматического переписывания инструкций |
| Mem0 OSS | Извлечение, обновление, поиск памяти; SDK или свой сервер | Рабочая альтернатива, но для этой задачи не выбран: Honcho имеет явно описанный сценарий user modeling в Hermes |
| Letta memory blocks | Постоянные блоки human/persona и их обновление агентом | Подходит при собственной агентной платформе; переход с Hermes ради этого не нужен |

Выбор — инженерная рекомендация по совместимости и соответствию задаче, а не доказанный независимым сравнением рейтинг качества русского языка. Улучшение именно нашего общения нужно подтвердить локальными испытаниями.

## Какие алгоритмы реально используем
1. Explicit feedback learning: явная коррекция владельца немедленно исправляет соответствующее правило общения.
2. Evidence-based preference consolidation: повторяющиеся сигналы разных сообщений обобщаются в устойчивое предпочтение; единичная эмоция или разовая просьба остаются локальными.
3. Honcho dialectic user modeling: история → фоновые выводы/профиль → релевантный контекст → следующий ответ.
4. Bounded reflection: после явной коррекции и периодически — краткая проверка своего ответа; обновлять только профиль общения, проверять отклонение от его требований. Использовать существующий review, не добавлять второй агент/таймер.
5. Versioned style prompt: ограниченный слой правил языка/длины/структуры с историей изменений и возможностью вернуть предыдущую версию.

## Проверенные особенности и ограничения
- USER.md загружается в system prompt как снимок на старте сессии. Изменить файл недостаточно для гарантированной подстройки текущего Telegram-диалога. Текущую явную коррекцию применять из живого контекста немедленно; если интеграция использует отдельный style overlay, проверить его загрузку перед каждым ответом. Новая сессия должна независимо подтвердить сохранение.
- background review может сохранять память и менять процедурные навыки. Это не разрешение переписывать весь system prompt, права или решения владельца.
- В документации memory providers Honcho фигурирует и как встроенная интеграция, и как плагин каталога. Проверять установленную версию; не выполнять обе процедуры установки вслепую.
- Локальный Honcho — отдельный сервис, ему нужны ресурсы и LLM-провайдер; self-hosted не значит нулевая стоимость inference. Не обещать бесплатную обработку.
- Honcho Cloud получает отправленные ему сообщения. Облако не включать автоматически: по умолчанию локальное хранение и действующий разрешённый LLM-маршрут. Не выгружать частные диалоги в GitHub или новый сторонний сервис.
- Модель стиля не должна обучаться на текстах самого ассистента как на пожеланиях владельца, ответах других ботов, клиентах или цитируемых документах. Сохранять изоляцию по реальному отправителю и проекту.
