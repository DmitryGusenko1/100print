# Правила работы Hermes с владельцем

Решение владельца от 2026-11-09. Это постоянное правило для задач сайта и админки проекта.

## Общение

- Пиши по-русски, коротко, чётко и по делу. Обычный ответ — 1–3 короткие строки.
- Сообщай результат, текущий блокер или следующий существенный шаг. Не пересказывай план и историю работы.
- Технические подробности, diff, логи, команды, архитектуру и длинные отчёты показывай только по запросу. Сохраняй их в рабочих артефактах проекта.
- Если решения владельца не требуется — выполняй уже порученную работу, затем кратко отчитайся. Не заканчивай словами «подтвердите», «продолжить?» или «могу сделать».
- Если действительно не хватает ответа — задай один конкретный вопрос. Независимую от него работу продолжай.
- Реальный блокер не скрывай: одна строка о том, что заблокировано, и одно необходимое действие/решение. Не выдавай повторные просьбы согласовать уже разрешённую работу за прогресс.
- Не заявляй об установке или публикации без проверки. «Записал задачу», «получил», «выполняю», «внедрил» — разные состояния.
- Примеры: «Готово: раздел доступен тебе в бете. Проверь список поставщиков.»; «Исправил поиск в бете. Можно проверять.»; «Нужен ответ: какую из двух цен считать закупочной?»

## Все новые функции — сначала в закрытую бету

- Все новые разделы, блоки и изменения поведения сайта/админки сначала внедряй на действующем сайте в закрытом beta-режиме для владельца.
- Владелец уже разрешил реализацию и выкладку порученных изменений в такую бету. Прежнее требование отдельного согласования каждой такой правки заменено этим порядком. Не запрашивай одно и то же одобрение повторно.
- Каждую beta-функцию обозначай видимой владельцу меткой «Бета». Остальные пользователи, включая сотрудников и администраторов, её не видят и не могут вызвать её API или открыть прямой URL.
- Проверяй доступ на сервере по действующей сессии и проверенному ID владельца. Скрытого меню, CSS, параметра URL, localStorage или общей роли ADMIN недостаточно.
- Реализуй управляемые состояния draft → beta → active, а также выключение/откат. Beta по умолчанию доступна только владельцу. Для остальных сохраняй действующий сценарий и ответы без beta-данных; не допускай утечки через кеши.
- Владелец тестирует на живом сайте. Его правки к бете выполняй внутри беты, не открывая функцию другим.
- Переводи конкретную функцию из beta в active только по явной команде владельца, относящейся к этой функции. Положительный отзыв, молчание или команда «внедряй планы» сами по себе не разрешают публичный выпуск. Не требуй второе одобрение, когда явная команда уже дана.
- При переводе в active сохраняй штатные права доступа раздела: внутренние функции админки не становятся общедоступными.
- Сначала настрой и проверь общий механизм закрытой беты; пока изоляция не обеспечена, не выкладывай функции всем под видом беты.
- Используй безопасные совместимые изменения данных и возможность отката. Не перезаписывай чужие незакоммиченные изменения, не сбрасывай рабочее дерево. Тестовые побочные эффекты не должны автоматически затрагивать клиентов и их заказы.
- Старые черновики и несовместимые архивные планы не превращай автоматически в задания. Выполняй актуальные поручения; при реальном противоречии задай один короткий вопрос.
- Отклонённые права на сеть/запись — отдельный технический блокер, а не отсутствие одобрения beta. Не обходи ограничения и не меняй настройку Hermes, которую ведёт другой исполнитель. Кратко назови конкретный недостающий доступ и ответственного за его предоставление.

## Приёмка

1. Владелец видит beta-ссылки, метки, страницы и может ими пользоваться.
2. Клиент, сотрудник, другой администратор и гость не получают beta-страниц/данных, в том числе по прямому URL/API и из кеша.
3. Обычный рабочий сценарий для остальных сохранён.
4. Правка владельца меняет только beta; active включается исключительно после его явной команды.
5. Отчёт владельцу укладывается в 1–3 короткие строки. Полные доказательства сохранены в проекте.
